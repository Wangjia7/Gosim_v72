# Pro v0.3.0 RC5 本地评估报告

**尚未达到验收要求。** 用户要求每个场景的官方总分较原始 Pro 至少提高 30%，并超过上传版本，同时每轮不超过 900 归一化 CPU 秒。当前开发证据：L1 总分提高 5.63–5.74%，L2 提高 11.22%，前瞻留出 L3 提高 11.06%、L4 提高 9.38%；四个场景均超过上传版本，但均不足 30%。这不是正式平台成绩，也不是最终版本推广结论。

当前代码为 **v0.3.0 RC5**，103 项测试通过（native Python 3.12，默认环境 0.373 秒、交付 manifest 环境 0.886 秒）。RC5 的新增修改仅为离线 QA 内部错误告警；观察策略沿用 RC4。测试证明所覆盖的行为，不证明分数增幅。L1 重复测量已完成；公开 L3/L4 前瞻冻结验证均已完成，本报告没有读取其输入或利用其结果调参。

## 历史实验、失败与负结果

全部已结算记录见 [完整结果表](RESULTS.md)、[JSON](results.json)、[CSV](results.csv)，由 [独立汇总脚本](collect_results.py)生成。缺少匹配原始或上传参考时，比较为 null / not comparable，不能通过验收。

RC1 无事件搜索的 L1/L2 合计总分较上传 +1.31%、较原始 +6.51%。历史最佳完整 L1 `rc2-fullbudget-refine` 为 **6600.590852**，计费 652.323 秒；它仍未达到 30%。RC2 请求宽度 12/20 实际被 planner 限制为 5，记录与成本归一化使用请求值；较大的基础候选上限仍有效。它不是当前修正源码的成绩，复现必须使用保存的 pre-width-fix ZIP。

RC3 修正宽度后暴露请求触发的零 science 密度桶错误，提前终止。该行明确为 **FAILED/INCOMPLETE**；任何部分结算分数都不是有效全程比较。RC4 修复后完成。宽度门控 1 的 L1 6592.094057 比门控 0 高约 0.07%，只有一次测量，不足以证明稳定优势；当前选定门控 0。

事件搜索、精确时间定价以及其他未选实验都保留在完整结果表中。两项时长策略消融均为负：lambda .60 为 6551.687157，kappa 1.3 为 6585.836507，对照门控 1 为 6592.094057；[详细消融记录](rc5-duration-ablations.md)。默认保持 lambda .45 / kappa 1，不把负结果隐藏为成功优化。

## 适用边界

源目录、原始 Pro 和上传源均保留；每次运行的保全检查与哈希见对应 `benchmark.json`。观察器运行时只读公开协议，不读取引擎真值或卡片文件；离线分析与测试证据不能进入观察策略。

本地原生运行没有验证托管平台固定容器镜像，也没有执行远程提交。上传的 `v4-public-test` 负分报告使用另一卡片、300 秒预算且开启模型；缺少该卡片和精确源码关联，无法精确复现，不能与正分 L1/L2 直接相减。

v0.4 的重大策略计划仍未批准、未实现。当前代码、测试与局部收益均不意味着 30% 目标已经完成；后续报告应继续公开失败、退化和缺失参考。
