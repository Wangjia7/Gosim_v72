# v3.2 正常路径优化

以官方 Python pro 为正常路径基线，保留 v3.1 的公开 initialize 路由和增强路径。内部目录名 official_pro 为兼容导入保留，其中的 planner/agent 已是优化后的分支。

- 每次决策内缓存物理预测、按目标/时长/program 的收益；C++ 先筛出真正落在光纤玻璃内的目标，再准备收益表。
- field × duration × program 联合搜索；每根光纤在共同 program 下重新挑选目标，使用相对已有最佳分数的新增贡献。
- 将目标饱和、required/request 门槛和请求截止端点加入时长候选；所有候选受仪器曝光上下限约束。
- 邻域范围覆盖整个试探视场及局部细化；中心光纤按运行时布局生成。
- 按实际搜索档位归档 CPU 开销，按剩余实际 CPU 预算限制每轮搜索；达到预算后返回已有合法候选。
- 读取运行时 required 阈值和罚分；完成度下界使用公开分数取整精度与可能的 program multiplier，独立于科学最佳分数。
- 保存曝光序号、结果、预测及维修阶段；数据丢失后回放有效曝光，重建完成度、校准和偏移证据，清除过期派生故障历史。重复结果不重复记账。
- 请求各自保存签发、截止、门槛、剩余数量和奖励；只对完整落在请求窗口内的曝光计入请求价值，同一批奖励最多计价一次。未完成批次使用打折进度估计，不把该估计描述成已经兑现的奖励。
- 修正 Moon 时刻与 LST 的一致性。
- 正常分支也接入已验证的 operator_nlp / anomaly_review 两个模型流程和专家 skill；结构化规则控制硬约束，建议带来源及有效期。
- 严格接受单个 JSON 或单个 JSON fence；模型失败、无密钥继续规则模式。重试共用一次调用总超时。
- 对重复的最近 16 个 decision sequence 回送原回复。

本批不移植 TypeScript/Rust，不引入长期资源桶或 beam 调度，不假定纯缓存会提高整季分数。WINDOW_URGENCY 为可测试开关，默认关闭；窗口工具用于请求几何可行性及实验，未来 Moon/天气下的 required 可完成机会数仍需独立验证。学习型遮挡 TTL 和更精细分段积分留作后续实验。

详细对照和限制见 VALIDATION.md。真实远程 API、Linux 容器部署以及网站成绩在本地不能代替实测。
