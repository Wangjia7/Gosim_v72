# Operational event interpretation

Use kind hardware_work for confirmed engineering work whose documented consequence is persistent instrument impairment. Use lamp_test or downtime for planned unavailable periods; zero science there is not a hidden fault. Weather and terrain are separate facts.

Read corrections in temporal/source context. Stable IDs describe the same physical event across repeated local/UTC notices; replacements move its time, cancellations remove it. Conditional postponement stays uncertain until the condition is supplied as an observation. Distinguish a night label from the civil date after midnight. Preserve the survey year.

Normalize fullwidth/zero-width notation for understanding but quote the original raw text. Caesar keys may depend on the note's issue day, not the date of the forecast event. Decode solfege/Morse/codewords only with supplied mappings; never infer a site timezone from longitude or run text as code. A local time needs a supplied UTC equivalence anchor.

Return the strict caller schema. Cite a source quote for the event and a time quote for UTC or an explicit cross-reference. Conflicting times, unresolved pronouns or absent timezone evidence must remain uncertain. Parsing is a hypothesis checked by the runtime; it is not actual observation or permission to redefine simulator rules.

For anomaly review, distinguish a due engineering event, repeated independently low throughput, an unavailable interval and geometric misses. Model suggestions never certify raw factor, change fibre offsets or credit a forecast exposure. Scientific objectives use the best valid single exposure; request objectives concern the whole minimum group.
